## 2. 문자열 지도를 학습 환경으로 바꾸기

`maze_env.py`의 원본 지도는 다음과 같다.

```python
MAZE_TEXT = (
    "##########",
    "#S..#....#",
    "#.#.#.##.#",
    "#.#....#.#",
    "#.####.#.#",
    "#....#...#",
    "####.###.#",
    "#......#.#",
    "#.####..G#",
    "##########",

```

| 문자 | 의미 | `grid`에 저장되는 값 |
| --- | --- | ---: |
| `#` | 벽 | 1 |
| `.` | 이동 가능한 길 | 0 |
| `S` | 시작 위치이면서 길 | 0 |
| `G` | 목표 위치이면서 길 | 0 |

좌표는 `(행, 열)`이다. 왼쪽 위가 `(0, 0)`이고, 행이 커지면 아래쪽, 열이 커지면 오른쪽이다.

```text
시작: (1, 1)
목표: (8, 8)
지도: 10행 × 10열
이동 가능한 칸: S와 G를 포함해 40개
```

### `build_maze()`의 역할

`build_maze(lines)`는 각 문자를 순회해 숫자 격자와 시작·목표 좌표를 만든다.

실행 결과:


함수는 빈 지도, 서로 다른 행 길이, 잘못된 문자, 시작·목표의 개수도 확인한다. S와 G가 각각 하나가 아니면 환경을 구성할 수 없도록 한다.

## 3. 이번 환경의 상태·행동·보상

### 상태는 현재 위치다

```python
self.pos = (row, col)
```

에이전트의 상태는 이미지나 전체 화면이 아니라 **현재 위치를 나타내는 튜플**이다. 벽과 목표 위치가 고정된 이 환경에서는 같은 위치와 같은 행동에 대해 같은 이동 결과와 보상이 나온다.

### 행동 번호와 좌표 변화

```python
UP = 0
DOWN = 1
LEFT = 2
RIGHT = 3

ACTION_DELTAS = (
    (-1, 0),
    (1, 0),
    (0, -1),
    (0, 1),
)
```

| 행동 | 번호 | 좌표 변화 |
| --- | ---: | --- |
| 위 | 0 | 행 -1 |
| 아래 | 1 | 행 +1 |
| 왼쪽 | 2 | 열 -1 |
| 오른쪽 | 3 | 열 +1 |

예를 들어 `(1, 1)`에서 오른쪽으로 가면 `(1, 2)`다. 위로 가려는 위치 `(0, 1)`은 벽이므로 현재 위치를 유지한다.

### 보상 규칙

```python
STEP_REWARD = -1
WALL_REWARD = -5
GOAL_REWARD = 100
```

| 결과 | 보상 | 다음 위치 |
| --- | ---: | --- |
| 일반 길로 한 칸 이동 | -1 | 이동한 위치 |
| 벽 또는 범위 밖으로 이동 시도 | -5 | 제자리 |
| 목표에 도착 | +100 | 목표 위치 |

목표 이동에서 `-1`과 `+100`을 함께 받는 것은 아니다. `step()`의 분기에 따라 **그 전이의 보상은 +100만 반환**된다. 벽도 `-1-5=-6`이 아니라 `-5`다.

이 설정에서는 같은 목표에 도달하더라도 불필요한 이동과 벽 충돌이 적은 경로가 유리하다. 이동 벌점만 준다고 모든 강화학습 문제가 자동으로 최단 경로 문제가 되는 것은 아니며, 여기의 고정 지도와 보상 규칙을 기준으로 이해한다.

## 4. `MazeEnv`의 메서드와 이동 처리

| 메서드 | 역할 |
| --- | --- |
| `__init__()` | 지도, 시작·목표, 행·열 크기, 현재 위치 준비 |
| `reset()` | 시작 위치로 돌아가 상태 튜플 반환 |
| `is_walkable(row, col)` | 지도 안의 길인지 확인 |
| `walkable_cells()` | 이동 가능한 모든 좌표를 리스트로 반환 |
| `step(action)` | 행동 하나를 적용하고 결과 반환 |

원본의 핵심 이동 코드는 다음과 같다.

```python
def step(self, action):
    if action not in (UP, DOWN, LEFT, RIGHT):
        raise ValueError(
            f"행동은 0, 1, 2, 3 중 하나여야 합니다. 받은 값: {action}"
        )

    row, col = self.pos
    d_row, d_col = ACTION_DELTAS[action]
    next_row = row + d_row
    next_col = col + d_col

    if not self.is_walkable(next_row, next_col):
        return self.pos, WALL_REWARD, False

    self.pos = (next_row, next_col)
    if self.pos == self.goal:
        return self.pos, GOAL_REWARD, True
    return self.pos, STEP_REWARD, False
```

`self.pos`를 바꾸기 전에 이동 가능 여부를 검사하므로 벽이면 위치가 바뀌지 않는다. 벽 충돌은 실패 경험이지만 **에피소드 종료는 아니다.**

### Gymnasium 환경과의 차이

이번 클래스는 직접 만든 Python 환경이지 Gymnasium의 `Env`를 상속한 클래스는 아니다.

```text
이번 reset(): 상태
이번 step():  다음 상태, 보상, done

Gymnasium reset(): 상태, info
Gymnasium step():  다음 상태, 보상, terminated, truncated, info
```

기존 CartPole 코드의 반환값 개수를 그대로 적용하면 안 된다. 이번 `done`은 목표 도착만 나타내며, 학습의 이동 횟수 제한은 `Q_learning.py`에서 별도로 처리한다.

목표 도착 후 행동을 막는 별도의 완료 플래그는 환경 안에 없다. 학습 코드와 플레이 코드가 `done`을 확인해 추가 이동을 멈추고, 다음 에피소드에서 `reset()`을 호출하는 구조다.

## 7. 배열 대신 딕셔너리로 Q표 저장하기

80일차에서는 고정 크기의 배열을 사용했다면, 이번 코드는 `(상태, 행동)`을 키로 사용하는 딕셔너리를 쓴다.

```python
self.q = {}

def q_get(self, state, action):
    return self.q.get((state, action), 0.0)
```

키의 모양은 다음과 같다.

```python
((1, 1), RIGHT)
```

상태도 튜플이고, 여기에 행동 번호를 더해 하나의 키를 만든다. 키가 없으면 `0.0`을 반환하지만 `q_get()` 호출만으로 새 항목이 저장되지는 않는다.

```python
from Q_learning import QLearningAgent
from maze_env import RIGHT

agent = QLearningAgent(alpha=0.5, gamma=0.95)
print(agent.q_get((1, 1), RIGHT))
print(len(agent.q))
```

실행 결과:

```text
0.0
0
```

실제 저장은 경험으로 갱신할 때 이루어진다.

```python
self.q[(state, action)] = new_value
```

지도에는 길 40개와 행동 4개가 있으므로 조합은 160개다. 실제 실행에서는 154개가 기록되었다. 목표에 도착하면 학습을 멈추므로 목표 상태에서 출발하는 행동은 실행하지 않는다.

**없는 항목의 0은 학습이 완료된 가치가 아니다.** 특히 이미 음수로 학습된 행동과 아직 확인하지 않은 0을 비교하면, 미경험 행동이 더 높게 평가될 수 있다.

## 8. 행동 선택과 동점 처리

기존 epsilon-greedy의 원리를 반복하기보다 이번 코드의 구현 차이를 본다.

```python
def best_action(self, state, random_tie=True):
    values = [
        self.q_get(state, action)
        for action in range(NUM_ACTIONS)
    ]
    best = max(values)
    candidates = [
        action for action, value in enumerate(values)
        if value == best
    ]
    if random_tie:
        return random.choice(candidates)
    return candidates[0]
```

| 호출 상황 | 동점 처리 |
| --- | --- |
| 학습 중 활용 행동 | 최대 Q 행동 중 무작위 선택 |
| 정책 보고·재생 | 후보 중 첫 번째 선택 |

초기 Q값은 모두 0이다. 학습 중에도 항상 첫 후보를 고르면 행동 0인 위쪽에 치우칠 수 있다. 재생에서는 동점 처리를 고정해 같은 Q표의 정책을 일관되게 보여 준다.

```python
def choose_action(self, state, epsilon):
    if random.random() < epsilon:
        return random.randrange(NUM_ACTIONS), True
    return self.best_action(state, random_tie=True), False
```

두 번째 반환값은 **어떤 분기로 행동을 골랐는지** 나타낸다. 탐험 분기에서도 우연히 최대 Q 행동이 선택될 수 있다. 반대로 활용 분기라도 동점 후보가 여러 개이면 행동이 무작위로 선택된다.

## 9. 첫 벽 충돌을 실제 숫자로 읽기

원본은 첫 에피소드의 첫 전이에 대해 갱신 전 숫자를 자세히 출력한다. 이번 실행의 첫 행동은 위쪽이었다.

```text
현재 상태: (1, 1)
행동: 위
다음 상태: (1, 1)
보상: -5
종료: False
기존 Q: 0
다음 상태의 최대 Q: 0
```

이미 배운 갱신식을 여기에 대입하면 다음과 같다.

$$
\text{target}=-5+0.95\times0=-5,
$$

$$
Q_{\text{new}}=0+0.5\times(-5-0)=-2.5.
$$

벽을 선택했지만 상태는 그대로이고, 현재 상태에서 그 행동의 평가만 바뀐다. 별도의 “벽 상태”로 이동하는 것이 아니다.

원본의 `update()`에서는 `done=True`일 때에만 미래 가치를 0으로 둔다. 벽 충돌은 `done=False`이므로, 학습이 진행된 뒤에는 제자리에 머문 다음 다른 행동으로 얻을 미래 가치도 반영한다.

## 10. 학습 설정과 한 에피소드의 흐름

| 상수 | 값 | 의미 |
| --- | ---: | --- |
| `EPISODES` | 500 | 학습 에피소드 수 |
| `MAX_STEPS` | 40 | 학습 에피소드당 행동 시도 한도 |
| `ALPHA` | 0.5 | Q값 갱신 학습률 |
| `GAMMA` | 0.95 | 할인율 |
| `EPSILON_START` | 1.0 | 첫 에피소드 탐험률 |
| `EPSILON_MIN` | 0.05 | 최소 탐험률 |
| `EPSILON_DECAY` | 0.992 | 에피소드 종료 후 곱하는 비율 |
| `LOG_EVERY` | 100 | 통계 출력 간격 |
| `RANDOM_SEED` | 2026 | 표준 `random` 모듈의 시드 |

한 에피소드 안에서 수행하는 핵심 순서는 다음과 같다. 아래는 원본 `train()`의 내부 코드 발췌다.

```python
current_epsilon = epsilon
state = env.reset()
total_reward = 0.0
reached_goal = False

for step_index in range(1, MAX_STEPS + 1):
    action, explored = agent.choose_action(state, current_epsilon)
    next_state, reward, done = env.step(action)
    agent.update(state, action, reward, next_state, done)

    total_reward += reward
    state = next_state
    if done:
        reached_goal = True
        break

rewards.append(total_reward)
successes.append(1 if reached_goal else 0)
epsilon = max(EPSILON_MIN, current_epsilon * EPSILON_DECAY)
```

### 이번 판의 탐험률을 고정한다

`current_epsilon`을 에피소드 시작에 저장하므로 한 판 안에서는 같은 탐험률을 사용한다. 판이 끝난 다음 감소시킨다.

| 에피소드 | 그 판에서 사용한 탐험률, 소수 셋째 자리 |
| ---: | ---: |
| 1 | 1.000 |
| 100 | 0.451 |
| 200 | 0.202 |
| 300 | 0.091 |
| 400 | 0.050 |
| 500 | 0.050 |

100번째 판에서 사용한 값은 $0.992^{99}$다. 그 판의 실행이 끝난 뒤 한 번 더 감소한다. 로그도 감소 후 값이 아니라 **이번 판에 실제 사용한 값**을 출력한다.

### 목표 도착과 이동 한도는 다르다

40번 안에 도착하지 못하면 반복문이 끝나 실패 0으로 기록된다. 이 경우 환경에서 `done=True`를 돌려준 것은 아니다. 마지막 전이의 Q 목표에도 다음 상태의 가치를 사용한다.

이는 코드가 40회를 경험 수집의 한도로 취급하는 방식이다. “남은 횟수 안에 도착할 확률”을 직접 학습하는 유한 시간 상태 모델과는 구분한다.

## 11. 학습과 탐욕 정책 검사를 분리하기

학습 중에는 탐험이 남아 있다. 학습된 Q표만 따라가면 어떤 경로를 선택하는지 보려면 따로 검사해야 한다.

`follow_policy(agent)`는 다음 일을 한다.

```text
새 환경 생성 -> 시작점으로 초기화
           -> 최대 Q 행동 선택, 동점은 고정
           -> 경로·보상 기록
           -> 목표, 벽 충돌, 재방문, 이동 한도 중 하나로 종료
```

원본의 검사 함수는 다음과 같다.

```python
def follow_policy(agent):
    env = MazeEnv()
    state = env.reset()
    path = [state]
    seen = {state}
    total_reward = 0

    for _ in range(MAX_STEPS):
        action = agent.best_action(state, random_tie=False)
        next_state, reward, done = env.step(action)
        total_reward += reward
        path.append(next_state)

        if done:
            return path, total_reward, True
        if next_state == state or next_state in seen:
            return path, total_reward, False

        seen.add(next_state)
        state = next_state

    return path, total_reward, False
```

여기에서는 Q값을 갱신하지 않는다. 이미 학습한 표를 읽는 것뿐이다.

### 같은 칸을 다시 만나면 중단하는 이유

이번 환경의 전이는 결정적이고, 이 검사에서는 동점 처리도 고정한다. 동일한 상태를 다시 만나면 같은 행동이 반복되므로 목표가 없는 순환을 계속 돌 수 있다. `seen` 집합으로 이를 빠르게 발견한다.

이 규칙은 **이번 고정된 결정적 정책 검사**에 적합한 종료 기준이다. 확률적 정책이나 이동 결과가 무작위인 모든 환경에서 재방문을 곧 실패로 취급해야 한다는 뜻은 아니다.

## 12. 학습 중 통계를 읽는 방법

기본 설정으로 직접 실행한 로그다. 평균은 원본의 출력 형식에 따라 소수 첫째 자리로 반올림했다.

| 에피소드 | 최근 100판 평균 보상 | 최근 100판 성공률 | 이번 판 탐험률 |

| 300 | 79.1 | 100.0% | 0.091 |
| 400 | 84.9 | 100.0% | 0.050 |
| 500 | 84.8 | 100.0% | 0.050 |

성공 여부는 `1`과 `0`으로 기록하므로 평균이 곧 성공 비율이다.

```python
successes.append(1 if reached_goal else 0)
success_rate = sum(success_slice) / len(success_slice)
```

시간 출력은 실행 장치에 따라 달라지므로 성능 기준으로 사용하지 않는다. 이번 학습 코드는 신경망이 아니라 표와 Python 표준 라이브러리를 사용한다.

## 13. 최종 정책: 14걸음, 보상 합 87

학습 후 `follow_policy()`로 확인한 경로는 다음과 같다.

```text
(1,1) -> (1,2) -> (1,3) -> (2,3) -> (3,3)
      -> (3,4) -> (3,5) -> (3,6) -> (4,6)
      -> (5,6) -> (5,7) -> (5,8) -> (6,8)
      -> (7,8) -> (8,8)
```

좌표는 15개지만 **이동은 좌표 사이의 전이 14번**이다.

```text
도착 여부: True
이동 횟수: 14
보상 합: 87
```

일반 이동 13번에 각각 -1, 마지막 목표 이동에 +100을 받으므로

$$
13\times(-1)+100=87
$$

이다. 이 출력의 보상 합에는 할인을 적용하지 않았다.

### 이번 경로가 최단임을 확인하기

시작 `(1, 1)`에서 목표 `(8, 8)`로 가려면 행 방향으로 최소 7칸, 열 방향으로 최소 7칸 이동해야 한다. 상하좌우 이동만 있으므로 어떤 경로도 14번보다 짧을 수 없다.

실제로 벽을 통과하지 않고 14번 만에 도착했으므로 이번 실행의 경로는 이 지도에서 최단 경로다. 학습 알고리즘에 정답 경로를 제공한 것은 아니며, 이 결과가 다른 모든 미로와 설정에서도 최단 경로를 보장한다는 뜻은 아니다.

## 14. 보상 합 87인데 시작 Q값은 왜 41.60인가?

실행 결과의 시작 위치 Q값은 다음과 같다.

| 행동 | 학습된 Q값, 소수 둘째 자리 |
| --- | ---: |
| 위 | 34.52 |
| 아래 | 35.58 |
| 왼쪽 | 34.52 |
| 오른쪽 | 41.60 |

Q값은 단순 보상 합이 아니라 **미래 보상에 할인을 적용한 리턴의 추정치**다. 위 14걸음 경로에 $\gamma=0.95$를 적용하면

$$
G=-\sum_{t=0}^{12}0.95^t+100\times0.95^{13}
\approx41.60105
$$

가 된다. 마지막 목표 보상은 첫 행동으로부터 14번째 보상이므로 할인 지수가 13이다.

```text
에피소드의 단순 보상 합: 87
같은 경로의 할인 리턴: 약 41.60
```

따라서 두 숫자가 다르다고 학습이나 보상 계산이 틀린 것은 아니다. 실제 Q표의 모든 항목이 이론적인 최적 가치와 정확하게 같다는 의미도 아니다.

### 벽으로 가는 행동의 Q값도 양수일 수 있다

시작점에서 위나 왼쪽을 선택하면 벽이다. 그런데 Q값은 34.52로 양수다.

이 행동은 즉시 -5를 받지만 에피소드가 끝나지는 않는다. 다음 상태가 같은 시작점이므로, 그다음부터 오른쪽을 선택해 목표에 도달할 미래 가치가 남아 있다.

$$
Q(s,\text{벽 방향})\approx-5+0.95\times41.60\approx34.52.
$$

**Q값이 양수라는 이유만으로 좋은 행동이라고 판정하지 않는다.** 같은 상태의 다른 행동과 비교해야 한다. 오른쪽의 41.60이 더 높으므로 오른쪽을 선택한다.

## 15. 정책을 문자로 확인하기

`report()`는 각 칸에서 최대 Q 행동을 골라 문자로 표시한다.

```text
^ : 위
v : 아래
< : 왼쪽
> : 오른쪽
```

이번 실행의 정책 지도:

```text
##########
#>>v#v>>v#
#^#v#v##v#
#^#>>>v#v#
#v####v#v#
#>>>v#>>v#
####v###v#
#v<<>>v#v#
#^####>>G#
##########
```

시작점도 정책 방향을 보여 주므로 문자 지도에서는 `S` 대신 `>`가 표시된다. 목표는 행동 방향 대신 `G`를 유지한다.

화살표는 **그 칸에 도착하면 선택할 행동**이지 실제로 지나간 경로 전체를 뜻하지 않는다. 시작점에서 방문하지 않는 칸에도 화살표가 있다. 학습되지 않은 행동의 기본 Q값이 0이라면 그 초기값과 동점 처리의 결과가 표시될 수도 있다.

## 16. 학습 시점별 Q표를 복사해 두기

최종 정책만 보면 처음에는 어디서 실패했는지 알기 어렵다. 원본은 일부 학습 시점의 Q표를 `snapshots`에 저장한다.

```python
shot = {
    "episode": episode,
    "q": dict(agent.q),
    "reached": reached_now,
    "steps": steps_now,
}
```

| 항목 | 의미 |
| --- | --- |
| `episode` | 몇 번째 에피소드까지 학습했는가 |
| `q` | 그 시점의 Q표 복사본 |
| `reached` | 그 시점의 탐욕 정책이 목표에 도달하는가 |
| `steps` | 검사에서 수행한 전이 수 |

### `dict(agent.q)`가 필요한 이유

```python
# 같은 딕셔너리를 계속 공유한다.
shot = {"q": agent.q}

# 현재 내용의 복사본을 만든다.
shot = {"q": dict(agent.q)}
```

첫 번째 방식은 이후 학습에서 표가 바뀌면 과거 스냅샷도 같은 표를 보게 된다. 원본은 딕셔너리 구조를 복사해 당시 값을 보존한다. 키가 튜플이고 값이 숫자인 이번 구조에서는 이 복사로 학습 시점의 내용을 유지할 수 있다.

### 모든 에피소드를 저장하는 것은 아니다

목표에 도달하는 정책을 발견하기 전, 실패 경로가 충분히 길어진 일부 시점과 마지막 시점을 저장한다. 초기 실패 시점은 최대 세 개까지 선택하고, 실패 경로 길이가 이전 기록보다 4걸음 이상 늘었는지도 본다.

이번 실행에서 저장된 시점:

| 에피소드 | 해당 시점의 탐욕 정책 검사 |
| ---: | --- |
| 1 | 2걸음 뒤 중단 |
| 9 | 6걸음 뒤 중단 |
| 19 | 10걸음 뒤 중단 |
| 500 | 목표까지 14걸음 |

여기의 걸음 수는 **학습 중 해당 에피소드가 움직인 횟수**가 아니다. 그 에피소드까지 학습한 표로 별도 검사한 결과다. 실패 경로가 길어졌다는 사실만으로 정책이 모든 면에서 더 좋아졌다고 단정하지 않는다.

스냅샷은 실행 중 메모리의 딕셔너리이며 파일로 저장하는 체크포인트는 아니다. 프로그램 종료 후 다시 쓰는 저장·불러오기 기능은 현재 코드에 없다.

## 18. 좌표를 화면 위치로 바꾸기

격자의 상태 좌표 `(row, col)`와 화면의 `(x, y)`는 순서가 다르다.

```python
x = MARGIN + col * CELL
y = MARGIN + row * CELL
```

원본은 `MARGIN=16`, `CELL=56`을 사용한다. 따라서 상태 `(1, 1)`의 칸 왼쪽 위는 다음 위치다.

```text
x = 16 + 1 × 56 = 72
y = 16 + 1 × 56 = 72
```

에이전트를 칸 중앙에 그릴 때는 `CELL // 2`를 더한다.

```python
center = (
    MARGIN + env.pos[1] * CELL + CELL // 2,
    MARGIN + env.pos[0] * CELL + CELL // 2,
)
```

**열이 가로 x, 행이 세로 y**라는 대응이 중요하다. 좌표 순서를 그대로 화면 좌표로 넣으면 미로 이동과 그림이 어긋날 수 있다.

## 19. 성공률 그래프의 의미

Pygame 패널의 그래프는 `successes`의 최근 50판 평균이다. 터미널의 최근 100판 로그와는 창 길이가 다르다.

```python
window = 50
total = 0.0

for index, value in enumerate(successes):
    total += value
    if index >= window:
        total -= successes[index - window]
        averages.append(total / window)
    else:
        averages.append(total / (index + 1))
```

새 결과를 더하고 범위를 벗어난 옛 결과를 빼므로, 매번 50개를 새로 합하지 않고도 이동평균을 계산한다. 초반 50판 전에는 실제 모인 개수로 나눈다.

| 항목 | 측정하는 값 |
| --- | --- |
| 터미널 평균 보상 | 최근 100판의 보상 합 평균 |
| 터미널 성공률 | 최근 100판의 목표 도착 비율 |
| 화면 그래프 | 최근 최대 50판의 목표 도착 비율 |
| 스냅샷의 `reached` | 그 시점 Q표로 검사한 고정 정책의 도착 여부 |

그래프 값 1은 보상 1점이 아니라 **해당 창의 성공률 100%**다.

또한 `watch_agent()`는 전체 학습의 `successes`를 그대로 전달받는다. 스냅샷 재생 시점에 맞춰 그래프를 잘라 그리는 코드는 없다. 초기 정책을 보고 있어도 아래 그래프는 **완료된 전체 학습 기록**이라는 점에 주의한다.

## 20. 실행 방법과 필요한 라이브러리

제공된 `requirements.txt`의 내용은 다음과 같다.

```text
pygame>=2.5.2
```

네 파일이 있는 폴더에서 다음 순서로 실행한다.

```bash
# 화면 표시 라이브러리 설치
python3 -m pip install -r requirements.txt

# 환경의 상태 전이와 보상 확인
python3 maze_env.py

# 사람이 직접 미로 플레이
python3 maze_game.py

# Q-Learning 학습 후 정책 재생
python3 Q_learning.py
```

위 명령은 같은 폴더에서 각각 실행한다. `Q_learning.py`의 파일명 대소문자도 맞춘다. 학습 자체는 `random`, `time` 등 표준 라이브러리만 사용하며, 화면 재생에 Pygame이 필요하다. 이번 미로 코드에 PyTorch나 Gymnasium을 설치할 필요는 없다.

### 원본 화면 코드의 운영체제 의존성

`make_font()`에는 다음 macOS 폰트 경로가 고정되어 있다.

```python
font_path = "/System/Library/Fonts/AppleSDGothicNeo.ttc"
font = pygame.font.Font(font_path, size)
```

이 경로가 없는 컴퓨터에서는 Pygame을 설치했더라도 폰트를 불러오지 못한다. 특히 Windows에 같은 경로가 있다고 가정하면 안 된다. 다른 운영체제로 옮길 때에는 해당 컴퓨터의 한글 폰트 경로를 사용하도록 이 부분을 별도로 조정해야 한다. 이 정리 과정에서는 원본 코드를 변경하지 않았다.

## 21. 이번 예제로 새롭게 연결한 내용

| 이미 다룬 원리 | 이번에 적용한 방식 |
| --- | --- |
| 상태·행동·보상 | 문자열 지도를 직접 해석해 환경 규칙으로 구성 |
| Q표 | `(위치 튜플, 행동)`을 키로 쓰는 딕셔너리 |
| 탐험·활용 | 학습 중 무작위 동점 처리, 재생 중 고정 동점 처리 |
| TD 갱신 | 실제 벽 충돌 경험의 숫자를 출력해 확인 |
| 정책 평가 | 학습 통계와 탐험을 끈 경로 검사를 분리 |
| 학습 과정 관찰 | 일부 시점의 Q표를 복사해 과거 정책 재생 |
| 결과 시각화 | 상태 좌표를 화면 좌표로 바꾸고 Q값·정책·성공률 표시 |

이번 실행에서는 시작점에서 오른쪽을 고르는 정책이 학습되었고, 14걸음으로 목표에 도착했다. 단순 보상 합은 87, 같은 경로의 할인 리턴은 약 41.60이었다.

> 핵심은 Q-Learning 수식을 다시 외우는 것이 아니라, **직접 만든 환경에서 나온 경험이 Q표를 바꾸고, 그 표가 다시 행동과 화면의 정책 표시로 이어지는 과정**을 이해하는 것이다.
